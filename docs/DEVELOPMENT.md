# Development

## Run

```bash
npm install
npm start                    # first run: welcome window; later launches: Home window
npm start -- ~/Desktop/x.png # open an image directly
```

On first launch a short welcome window asks for **Screen Recording** permission (macOS), shows the shortcuts and explains the menu bar icon.
macOS needs a relaunch after the permission is granted; the welcome window reopens at the same step until it is finished.
After that, opening OneShot yourself (Finder, Dock, Start menu, or *Home & Settings…* / ⌘, in the menu bar) shows the **Home** window: capture buttons, recent captures and settings.
Closing it leaves OneShot running in the menu bar (system tray on Windows/Linux). A launch at login starts silently.
In dev, macOS grants the permission to the terminal you ran `npm start` from; relaunch after allowing it.
Settings live in `settings.json` in the user-data folder: `captureDir`, `autoCopy`, `previewCorner` (`top-left` … `bottom-right`), `previewSize` (`small`, `medium`, `large`).

Reset the welcome flow by deleting `~/Library/Application Support/OneShot/settings.json`, or use *Welcome tour → Show* in Home.
Bump `ONBOARDING_VERSION` in `main.js` when the welcome flow changes enough that existing users should see it again.

## Test

```bash
npm test        # unit tests (document model, history, perspective warp), node:test, no deps
npm run smoke   # launches the real app (editor, capture overlay, welcome, Home) and fails on renderer errors
npm run lint    # ESLint (eslint.config.mjs)
npm run check   # lint + unit tests + smoke
```

### Debug hooks

Dev builds only. They use an isolated profile in the temp folder, so they never hand off to a running OneShot.

| Variable | Effect |
|---|---|
| `ONESHOT_DEBUG_SHOT=/path.png` | screenshot the first window after it loads |
| `ONESHOT_DEBUG_JS="…"` | run this JS in that window before the screenshot (a throw is reported) |
| `ONESHOT_DEBUG_QUIT=1` | quit after the screenshot |
| `ONESHOT_DEBUG_OVERLAY=/img.png` | open the post-capture overlay for an image |
| `ONESHOT_DEBUG_SELECT=/img.png` | open the Windows/Linux area selector over an image |
| `ONESHOT_DEBUG_FALLBACK=1` | use the Windows/Linux capture path (selector) on a Mac |
| `ONESHOT_DEBUG_WINDOW=home` | open `home`, `onboarding` or `launcher` directly |

## Build

| Command | Output in `dist/` |
|---|---|
| `npm run dist:mac` | `.dmg` + `.zip`, Apple Silicon and Intel |
| `npm run dist:win` | NSIS installer `.exe`: x64, ARM64, and one combined installer |
| `npm run dist:linux` | `.AppImage` + `.deb`, x64 |
| `npm run dist:all` | all of the above |
| `npm run dist` | current platform only |
| `npm run pack` | unpacked app for a quick local try |

Artifacts are named `OneShot-<version>-<os>-<arch>.<ext>`.
macOS can build all three platforms. Windows and Linux hosts can build their own platform (and Linux).
Local macOS builds are signed automatically if a Developer ID certificate is in the keychain. They are notarized only through `npm run release:mac` (below). CI builds are unsigned.
The app icon is `build/icon.png`, generated by `npm run icon`.

## Release

### Where the version lives
`package.json` → `version` is the only place to change it. The app reads it at runtime (tray menu, macOS *About OneShot*), and the build uses it for file names (`OneShot-<version>-<os>-<arch>.<ext>`) and the Git tag (`v<version>`). Don't edit it by hand for a release; the commands below do it.

We use [semver](https://semver.org): **patch** for fixes, **minor** for new features, **major** for breaking changes (e.g. dropped platforms or settings that no longer carry over).

### Ship a new version
1. Be on `main`, with everything committed and pushed.
2. Run one of:
   ```bash
   npm run release:patch   # 0.1.0 → 0.1.1
   npm run release:minor   # 0.1.0 → 0.2.0
   npm run release:major   # 0.1.0 → 1.0.0
   ```
   This runs the tests, bumps `package.json` + `package-lock.json`, commits `Release vX.Y.Z`, creates the local tag `vX.Y.Z`, pushes the commit, and then runs `npm run release:mac`, which:
   - installs, lints and runs the tests;
   - builds both mac architectures, signs them, notarizes them (a few minutes), and checks them with `codesign` and `spctl`;
   - pushes the tag, creates the GitHub Release (with generated notes) and uploads the DMGs and zips.
3. The tag push starts the [Release workflow](../.github/workflows/release.yml), which adds the Windows and Linux builds to the same release (about 10 minutes). Check it under GitHub → Actions.

| Platform | Built by | Signed |
|---|---|---|
| macOS arm64 + x64 (`.dmg`, `.zip`) | locally, `npm run release:mac` | Developer ID: Digital Vibes GmbH (8HFX6YPXXN), notarized |
| Windows x64 + ARM64 (`.exe`, NSIS) | GitHub Actions, on the `v*` tag | no |
| Linux x64 (`.AppImage`, `.deb`) | GitHub Actions, on the `v*` tag | no |

### When something goes wrong
- **Mac build or notarization failed** after the version commit was pushed: fix the cause, then run `npm run release:mac` again. It reuses the existing local tag, and it doesn't bump again.
- **Windows/Linux CI failed:** fix it on `main`, then rebuild that tag with Actions → Release → *Run workflow* → `tag: vX.Y.Z`. Note that this builds the tagged commit, so a code fix needs a new patch release.
- **Bump the version without releasing:** `npm version patch --no-git-tag-version` (only edits the files).

### Local builds only
- `SKIP_UPLOAD=1 npm run release:mac`: signed and notarized build in `dist/`, with no tag and no upload. This works on a dirty tree.
- `NOTARIZE=0 SKIP_UPLOAD=1 npm run release:mac`: signed but not notarized. It's quicker, but Gatekeeper rejects it, so don't ship it.
- `npm run dist:mac` / `dist:win` / `dist:linux`: plain builds, see [Build](#build).

### One-time setup on a new Mac
- The Developer ID certificate for Digital Vibes GmbH must be in the login keychain (`security find-identity -v -p codesigning`).
- A notarytool keychain profile for team 8HFX6YPXXN. The script uses `splatcraft` by default (shared with SplatCraft); set `APPLE_KEYCHAIN_PROFILE` to use another. Create one with
  ```bash
  xcrun notarytool store-credentials <name> --apple-id <apple id> --team-id 8HFX6YPXXN
  ```
  It asks for an app-specific password (appleid.apple.com → Sign-In and Security).
- `gh auth login` with push access to the repo.
- Entitlements (hardened runtime) are in `build/entitlements.mac.plist`.

## Default image viewer

After installing, set OneShot as the default app for images:
- **macOS:** select a PNG in Finder → Get Info → *Open with: OneShot* → **Change All…**
- **Windows:** Settings → Apps → Default apps → OneShot
- **Linux:** the `.deb` registers the image types; pick OneShot under *Open With* in your file manager.

## Code structure

```
main.js                 menu bar, shortcuts, capture, windows, IPC
image-types.js          image extensions OneShot opens (kept in sync with package.json by a test)
preload.js              safe bridge (window.oneshot)
renderer/util.js        pure helpers (colors, clamp)
renderer/lib.js         DOM + bridge helpers shared by the pages
renderer/editor/        viewer + editor (ES modules)
  app.js                entry: history, loading, modes/tools, keyboard
  model.js              document model constants + pure helpers (tested)
  warp.js               perspective homography + bilinear warp (tested)
  state.js              shared editor state
  draw.js               painting + hit testing
  view.js               fit/zoom, canvas sizing, redraws
  pointer.js            mouse/pen interaction
  text.js               in-place text editing
  ops.js                crop/perspective/rotate/flip + export
  ui.js                 dock, popovers, inspector
  icons.js              toolbar icons
renderer/overlay.*      post-capture quick-access card
renderer/pin.*          floating pinned screenshot
renderer/launcher.*     floating capture bar
renderer/onboarding.*   first-run welcome: permission, shortcuts, menu bar
renderer/home.*         Home window: capture, recent captures, settings
renderer/panel.css      shared styles of the welcome and Home windows
renderer/tokens.css     design tokens shared by all pages
scripts/                icon generator, smoke test, PNG encoder, release-mac.sh
test/                   unit tests
```

The editor document is a raster `base` plus vector annotations plus background settings. Annotations stay editable until export; crop shifts them, while perspective, rotate and flip burn them into the image first. Undo stores snapshots that share bitmaps rather than copying them.
